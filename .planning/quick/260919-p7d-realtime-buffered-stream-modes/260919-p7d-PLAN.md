<objective>
Stop the frequent "drift" reconnects and give the user a real choice between a
realtime stream and a buffered one.

Purpose: the drift watchdog compared the demuxer packet cache against the
*audio output* buffer setting plus 1 s. Those are unrelated buffers, and with
`cache=yes` mpv ignores `demuxer-readahead-secs` (the manual: `cache-secs`,
default ~1000 s, wins), so the packet cache is bounded only by
`demuxer-max-bytes`. Every playback stall (Doze, audio-focus duck, GC, WiFi
hiccup, the NVR's start-up burst) leaves a permanent residue in that cache
that nothing drains at 1x speed. Once the residue crosses the small margin
(0.2 s at the "low latency" slider position) the app stop+opens the RTSP
session every cooldown period — a 2–4 s audio gap, a "reconnecting" status,
downtime in the health summary, level/tap reset — for a stream that was
actually fine.

Output: a two-tier live-edge guard (gentle speed catch-up first, reconnect
only past a hard limit), a Realtime / Buffered stream mode setting with the
matching mpv cache-pause tuning, and tests.
</objective>

<context>
mpv facts verified against DOCS/man (options.rst, mpv.rst, af.rst):
- `--demuxer-readahead-secs` "is mostly ignored" when the cache is enabled;
  `--cache-secs` (default very high) overrides it, so readahead is bounded by
  `--demuxer-max-bytes`.
- Low-latency section: "For livestreams, data can build up due to pausing the
  stream, due to slightly lower playback rate, or 'buffering' pauses" and
  "`--speed=1.01` may help for live sources".
- `--audio-pitch-correction` (default yes) auto-inserts `scaletempo2`, an mpv
  built-in WSOLA filter (audio/filter/af_scaletempo2.c), not an FFmpeg lavfi
  filter — so the stripped FFmpeg build in media_kit is irrelevant to it.
  media_kit's own `Player.setRate` relies on exactly this path.
- `--cache-pause` / `--cache-pause-initial` / `--cache-pause-wait=<s>` are
  mpv's native jitter buffer: pause on underrun until N seconds are cached.
- media_kit sets `cache-on-disk=yes` on every player; pin it to `no`.
</context>

<objective>
Add a peer-to-peer mode: one phone hosts (acts as a camera / audio source), another
pairs with it over the LAN via a unique code — typed or scanned from a QR — with
automatic host discovery, and monitors it like any other camera.
</objective>

<design>
Transport: the host serves an endless WAV (PCM16 mono 16 kHz) over plain HTTP on
the LAN. libmpv/FFmpeg plays `http://host:port/roomtone/v1/audio.wav?token=…`
natively, so the monitor side is the unchanged media_kit pipeline. A side channel
`/roomtone/v1/status` supplies the host-computed RMS level, since a constant-bitrate
PCM stream gives the bitrate-based meter nothing to work with.

Discovery: dependency-free UDP beacon on port 47830. Chosen over mDNS plugins for
determinism (loopback-testable in `flutter test`) and because Android NSD is
flaky; QR and manual address entry are the fallbacks.

Pairing: host shows a crypto-random 6-digit code; POST /pair with the code returns
a 32-byte bearer token; host persists SHA-256(token) per paired device and rotates
the code after each successful pairing; 5 failures/min lock pairing for 60 s.

Host background: flutter_foreground_task with `microphone` + `mediaPlayback`
service types; manifest gains RECORD_AUDIO / FOREGROUND_SERVICE_MICROPHONE.
</design>
